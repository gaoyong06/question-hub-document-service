# 图片上传失败（No such file: xxx. png）分析

## 一、现象

- 日志：`Failed to upload image to asset-service: image_path=.../f2ea6c17386f4796b4ca51856521c9cb. png, error=[Errno 2] No such file or directory`
- 注意路径中 **点与扩展名之间多了一个空格**：`xxx. png` 而非 `xxx.png`
- 转换后的 markdown 里部分图片仍是临时路径 `/tmp/.../xxx. png`，未替换为 asset URL

## 二、根因

在 `document_parser.docx_to_markdown` 中，原先顺序为：

1. 先把占位符 `{{IMAGE_N}}` 替换成 `![](/tmp/.../uuid.png)`
2. 再对整段做**题号/选项规范化** `_normalize_markdown_list_markers`

选项规范化使用的正则是：`([A-Da-d])[\.．、]\s*` → 替换为 `\1. `（在字母与点后加空格）。

当图片路径为 `/tmp/.../f2ea6c17386f4796b4ca51856521c9cb.png` 时，路径末尾的 **`b`** 会匹配 `[A-Da-d]`，紧跟的 **`.`** 匹配 `[\.．、]`，于是整段里的 `b.` 被替换成 `b. `，导致路径变成 `...c9cb. png`。实际磁盘上的文件名是 `...c9cb.png`（无空格），因此上传时 `open(image_path)` 报错「文件不存在」。

## 三、修复（保证流程正确，不写地址）

**只改 document_parser 的流程**：先做题号/选项规范化，再替换图片路径。这样规范化时段落里仍是 `{{IMAGE_N}}`，不会包含真实路径，路径不会被正则误改。

```python
# 先做题号/选项序号规范化（仅对占位符段落），再替换为图片路径
s = _normalize_markdown_list_markers(s)
for j, path in enumerate(image_paths):
    s = s.replace("{{IMAGE_%d}}" % j, "![](%s)" % (path,))
```

不在 image_processor 中做「文件不存在时把 . png 改成 .png 再重试」等防御逻辑，避免用容错掩盖流程错误；只要流程正确，生成的地址就不会错。

## 四、如何保证图片都能上传成功

从源头保证流程正确：部署上述修改后，新转换的 docx 会先规范化再写路径，生成的 markdown 中图片路径正确，上传即可成功。对之前因流程错误产生错误路径的文档，重新触发一次转换即可。
