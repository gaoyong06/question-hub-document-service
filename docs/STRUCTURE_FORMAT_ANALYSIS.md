# 结构优先：用格式信息辅助大题/小题判断 — 分析

## 结论

**可以。** 在「结构优先」的前提下，用**字体大小、缩进、段落样式**等格式信息来辅助判断大题和小题，是可行且推荐的；和纯文字判断一起用，能提高鲁棒性并减少对「一. 二.」「1. 2.」等固定写法的依赖。

---

## 1. 格式能提供什么信息

| 格式维度 | 典型用法 | 对应结构 |
|----------|----------|----------|
| **段落样式 (Style)** | 标题 1/2、标题、正文 | 大题 ≈ 标题级样式；小题 ≈ 正文/列表 |
| **字号 (Font size)** | 大题标题 16–18pt，正文 10.5–12pt | 明显大于正文的段落 → 可能为大题 |
| **缩进 (Indent)** | 左缩进、首行缩进 | 无缩进/小缩进 → 标题/大题；有首行或左缩进 → 小题内容 |
| **加粗 (Bold)** | 标题加粗 | 整段加粗 + 短行 → 可能为大题标题 |

- 大题：多为**标题样式**或**更大字号 / 加粗**，且**缩进较小或为 0**。
- 小题：多为**正文样式**、**正常字号**，常有**首行缩进或左缩进**（题号后缩进）。

所以：**不仅依赖文字内容，也依赖格式**，是合理的。

---

## 2. 在当前技术栈里能拿到什么

### 2.1 Word（python-docx）

- **段落样式**：`paragraph.style.name`（如 `"Heading 1"`, `"标题 1"`, `"Normal"`）。
- **缩进**：`paragraph.paragraph_format.left_indent`、`first_line_indent`（可为 `None`，需转成可比较的数值，如 Pt）。
- **字号**：在 **Run** 上，`run.font.size`；段落可取其 runs 的「最大字号」或「首 run 字号」作为该段代表字号（很多试卷大题标题整段统一字号）。
- **加粗**：`run.bold`；可定义「段落内是否多数/全部为加粗」表示该段为加粗段。

目前 `_extract_paragraphs_with_images` 只返回 `List[str]`，没有带格式。若要「结构优先 + 格式辅助」，需要**同时输出每段的格式信息**（见下节）。

### 2.2 非 Word（MarkItDown → Markdown 文本）

- 转成 Markdown 后，**没有**直接的字体、缩进等格式。
- 但 Markdown 本身有**结构**：`# ## ###` 是标题层级，可等价为「格式」：  
  `#` / `##` → 大题，其下到下一个同级或更高级标题之前 → 该大题下的小题/内容。
- 因此「格式辅助」在 Word 路径用**真实格式**，在 Markdown 路径用**标题层级**即可，二者统一成「层级/重要性」再参与结构判断。

---

## 3. 如何用格式做「结构优先」判断

思路：**先按格式推断层级（大题 vs 小题），再结合文字做校验与映射**。

### 3.1 大题（Section）

- **强信号**：段落样式为标题类（如 `Heading 1/2`、`标题 1/2`、或 style.name 含 "Heading"/"标题"）。
- **强信号**：该段**代表字号**明显大于正文（例如 ≥14pt 且正文约 10.5–12pt）。
- **弱信号**：整段加粗 + 行较短（如 < 80 字）。
- **弱信号**：左缩进/首行缩进为 0 或很小，且下一段缩进更大 → 像「标题 + 下属内容」。

遇到**任一强信号**或**多个弱信号**，可把该段视为**可能的大题边界**；再与现有规则合并：

- 若该段同时匹配「一. 二.」或宽松大题关键词 → 确认为大题。
- 若该段**仅**凭格式像标题（无明确题号/题型词），也可当作大题，标题文本用该段全文（或截断）。

### 3.2 小题（Question）

- 在大题边界内，**非大题格式**的段落都视为「该大题下的内容」。
- 小题边界再用**多模式拆分**（1. / a. / ①② / (1)、双换行、单换行），和现在一致；若某段有**首行缩进明显**（如 2 字符）、且与上一段同属「正文」格式，可辅助判断「新一题开始」（可选，不强制）。

即：**大题由「格式 + 文字」共同决定；小题仍以「大题内的块 + 题号/段落拆分」为主，格式作辅助。**

## 4. 实现要点（与现有代码的关系）

1. **带格式的段落表示**
   - Word 路径：在 `_extract_paragraphs_with_images` 中，除文本外，为每个段落输出**格式信息**，例如：
     - `style_name: str`（如 "Heading 1", "Normal"）
     - `font_size_pt: Optional[float]`（该段代表字号，如 runs 最大字号）
     - `left_indent_pt: float`、`first_line_indent_pt: float`（无则 0）
     - `is_bold: bool`（整段是否视为加粗）
   - 下游可约定：返回 `List[Tuple[str, Optional[ParagraphFormatInfo]]]`，或 `List[str]` + 并行的 `List[ParagraphFormatInfo]`，供 `_parse_structure` 使用。

2. **仅在 Word 路径使用格式**
   - 非 Word（如 MarkItDown 转出的 Markdown）没有这些字段，则 `ParagraphFormatInfo` 为 `None`，`_parse_structure` 退化为**仅按文字 + 标题层级（# ##）** 判断，与现有逻辑一致。

3. **结构解析中的优先级**
   - 有格式时：**先看格式**（是否标题样式/大字/无缩进）判定「可能大题」；再与文字规则（一. 二.、题型词、第X部分）合并，避免误杀。
   - 无格式时：完全沿用当前「文字 + 宽松大题 + 小题多模式拆分」逻辑。
   - 这样既做到「结构优先」，又做到「有格式时用格式，无格式时不依赖格式」。

4. **Markdown 路径的「格式」**
   - 若上游把 `# ## ###` 转成带层级的结构（如 `level: 1/2/3`），可传入 `_parse_structure`：level 1/2 视为大题边界，其下为小题内容，再在内容里做多模式拆分。

---

## 5. 注意点与边界

- **样式/字号不统一**：很多试卷是手动调字号、加粗，而不用「标题」样式；所以格式只作**辅助**，正文仍需要「无格式」的文本规则兜底。
- **缩进单位**：docx 里可能是 `Twips`/`Emu`，需统一成 Pt 或同一单位再比较。
- **兼容性**：格式增强只加在「带格式的路径」上，纯文本路径行为不变，保证不破坏现有行为。

---

## 6. 小结

- **是否可以通过字体、缩进等格式判断大题和小题？**  
  **可以**，且与「结构优先」一致：先根据格式 + 文字得到**层级结构**（哪里是大题、哪里是大题下的内容），再在内容里拆小题、映射业务。
- **和「不只依赖文字」的关系**：  
  把「格式」当作与「一. 二.」「选择题」等文字并列的**结构信号**；有格式就用格式，没有就只用文字，这样既增强识别率，又不过度依赖某一种写法。

若要落地，下一步就是在 `_extract_paragraphs_with_images` 中增加格式提取，并让 `_parse_structure` 接受可选格式信息，在 Word 路径中实现上述「格式 + 文字」的大题/小题判断逻辑。
