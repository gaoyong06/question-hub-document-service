# 试卷解析问题分析与修复方案

## 问题现象

- **源文件**：一年级上册数学期末测试卷（达标题）.docx  
- **预览地址**：https://www.zhijuanyun.com/dashboard/papers/ad4fd148-e24f-4dc8-bb32-2d7235ab4f91  

### 问题 1：层级/结构未识别

- **期望**：识别试卷标题「一年级上册数学期末测试卷」、大题标题（如「一.选择题(共6题，共12分)」「二.判断题」…「六.解答题」）以及卷末「参考答案」区块，并在预览中体现层级。
- **现状**：识别结果只有「一、题目」，没有试卷标题与大题分组。

### 问题 2：图片缺失

- **期望**：试卷中的图片应自动上传到 asset-service，并在最终试卷内容中展示。
- **现状**：解析后的试卷中没有任何 docx 内嵌图片，内容不完整。

### 问题 3：答案为空

- **期望**：题目答案来自卷末「参考答案」。
- **现状**：识别后的题目答案均为空，参考答案未被解析并关联到题目。

---

## 根因分析

### 当前 docx 处理流程（document_consumer + document_parser）

1. **document_consumer**：对 `.docx` 直接调用 `DocumentParser.parse_document(file_path)`，**不走** MarkItDown，也**不调用** image_processor。
2. **document_parser.parse_document**：
   - 使用 **python-docx** 仅读取 `doc.paragraphs` 的 **纯文本**（`para.text`）。
   - 未使用段落样式（标题、正文）、未提取内嵌图片、未识别「参考答案」区块。
   - 将全部段落拼成 `full_text` 和 `paragraphs` 列表，再交给 `_extract_questions`。
3. **\_extract_questions**：用**正则**按题型（单选/多选/填空/判断/解答）从整篇文本中匹配题目；且当前正则要求**题目紧跟「答案：X」**（如 `答案：A`）才会识别答案。

由此得到三个根因：

| 问题 | 根因 |
|------|------|
| **问题 1 层级** | ① 未使用 docx 的段落样式（标题/正文）区分试卷标题、大题标题、参考答案。② 下游 question-hub-service 的 `AutoCreatePaperFromConversion` 写死一个 section，标题为「题目」，试卷标题来自文件名，未使用解析出的结构。 |
| **问题 2 图片** | docx 分支只处理了 `doc.paragraphs` 的文本，**完全没有**从 docx 中提取图片（python-docx 支持通过 `document.part.related_parts`、段落 runs 中的 drawing 等获取图片）。且 docx 不经过 MarkItDown，因此也不会走现有的「Markdown 图片 → 上传 → 替换」流程。 |
| **问题 3 答案** | 当前正则只匹配「题目 + 紧跟的 答案：X」。实际试卷是**卷末集中「参考答案」**（如「1. A  2. B  3. 对  …」），与题目分离，因此从未被识别，题目答案字段为空。 |

### 下游数据结构（question-hub-service）

- 转换结果消息为 **扁平题目列表**：`result: []QuestionResult`，无试卷标题、无 section 列表。
- `AutoCreatePaperFromConversion` 根据 `questionIDs` 创建**一个**默认 section（标题「题目」），试卷标题由 `extractFileName(fileUrl)` 得到。
- 要支持「试卷标题 + 多大题」的层级，需要要么扩展结果协议（如增加 paper_title、sections），要么在 `QuestionResult` 中增加 section 信息（如 section_title），由 Go 端按 section 分组生成多个 `PaperSection`。

## 修复方案概览

### 问题 1：层级/结构

- **document_parser（Python）**  
  - 在解析 docx 时利用段落样式或规则识别：  
    - 试卷标题（如首段或首行大标题）、  
    - 大题标题（如「一.选择题」「二.判断题」…「六.解答题」）、  
    - 「参考答案」区块（标题或首行含「参考答案」）。  
  - 在现有 `QuestionResult` 上增加可选字段，例如：  
    - `section_title`：所属大题标题；  
    - `section_order`：大题顺序。  
  - 这样不改动「扁平题目列表」主结构，Go 端可按 `section_title` + `section_order` 分组生成多个 section。
- **question-hub-service（Go）**  
  - 在 `mq.QuestionResult` 中增加 `SectionTitle`、`SectionOrder`（可选）。  
  - `AutoCreatePaperFromConversion`（或新建逻辑）：  
    - 若存在 section 信息，则按 section 分组题目，为每个 section 创建一个 `PaperSection`（标题用 `SectionTitle`，顺序用 `SectionOrder`）。  
    - 试卷标题可优先使用解析结果中的 title（若 Python 通过某字段传），否则继续用文件名。

### 问题 2：图片

- **方案 A（推荐）**：在 **docx 解析分支**中增加「从 docx 提取图片」逻辑：  
  - 使用 python-docx 遍历 document（如 `element.xpath`、`paragraph.runs` 中的 drawing、或 `document.part.related_parts`）取出图片 part，解码为临时文件。  
  - 对每个图片调用现有 **ImageProcessor.upload_image_to_asset_service**（需提供同步封装或在此处用 asyncio.run），得到 URL。  
  - 在对应题目内容中：要么在 content 中插入 Markdown 图片语法 `![desc](url)`，要么将 URL 加入该题的 `images` 列表（与下游展示约定一致）。  
  - 需要约定：图片与「当前题目」的对应关系（按出现顺序与题目顺序关联，或按段落顺序插入到对应题目 content）。
- **方案 B**：docx 也先经 **MarkItDown** 转为 Markdown（若 MarkItDown 支持 docx 且会导出图片到本地），再走现有「Markdown → 图片上传 → 解析」流程；这样复用现有图片逻辑，但需确认 MarkItDown 对 docx 的图片导出质量与格式。

### 问题 3：答案

- 在 **document_parser** 中：  
  - 先根据「参考答案」区块识别（标题或首行含「参考答案」），得到从该段落到文档末尾或下一大标题的**参考答案文本**。  
  - 用正则或简单解析得到「题号 → 答案」的映射，例如：  
    - `1. A`、`2. B`、`3. 对`、`4. （1）42 （2）...` 等。  
  - 在 _extract_questions 得到题目列表后，**按题号或题目顺序**把参考答案填回每个 `QuestionResult.answer`（若题目本身未带「答案：X」则用参考答案块中的值）。

---

## 建议实现顺序

1. **问题 3（答案）**：先实现「参考答案」区块识别 + 题号→答案解析 + 回填到题目。不改协议、不改下游，见效快。  
2. **问题 2（图片）**：在 docx 分支增加图片提取与上传，并写入题目 content 或 images。  
3. **问题 1（层级）**：在 Python 增加 section 信息输出，在 Go 端按 section 分组建卷，并优先使用解析出的试卷标题（若协议扩展）。

## 附录：一年级-数学目录 docx 适配说明

针对 `/Users/gaoyong/Downloads/题库/一年级-数学/` 下多份 docx 的实测与适配：

| 文件 | 结构特点 | 解析适配情况 |
|------|----------|--------------|
| 一年级上册数学左、右练习题 | 题号全角点「1．」、一/二/三、填空题+判断题+作图题、参考答案： 1．(1)5… | 题号支持 `[\.．、]`；答案区块优先「参考答案」避免误用前面「答案」；能解析出题目+答案+图片+大题 |
| 一年级上册数学期中/期末测试卷（完整/精选/达标题） | 一.选择题(共6题…)…六.解答题、卷末「参考答案」下列出 一.选择题 1.A 2.B… | 答案区块过滤「一.选择题」等大题标题行，避免混入答案列表；图片为 VML（w:pict+v:imagedata），已支持 |
| 一年级数学上册练习题 | 仅 2 段、无大题标题、无「参考答案」、题号格式 1填一填、(1)(2) | 无集中参考答案、题号格式特殊，目前可能只解析出少量或 0 题，属格式差异 |

**本次为兼容该目录做的代码改动：**

1. **VML 图片**：在 `_extract_paragraphs_with_images` 中增加对 `w:pict` + `v:imagedata` 的 `r:id` 解析，使期中/期末卷中 WPS 或旧版 Word 生成的图片能被提取并占位。
2. **全角点题号**：填空题按段落识别题头时，题号由 `\d+[\.、]` 改为 `\d+[\.．、]`，支持「1．看图填空」等形式。
3. **参考答案区块**：优先从「参考答案」开始截取，其次「标准答案」，最后「答案」，避免题干中的「答案」二字被当成区块起点。
4. **答案列表过滤**：按题号分割出的片段中，若整段为大题标题（如「一.选择题」「二.判断题」），则跳过不加入答案列表，避免与题目一一对应错位。

**已知限制：**

- 期中/期末卷单份解析因全文正则较多，耗时可至约 30–40 秒，后续可考虑按「参考答案」分块或先按段落粗分再匹配以提速。
- `.doc` 非 zip/docx 格式，当前仍依赖 MarkItDown 等转换，未在本次单独测试。

## 参考答案区块的层级与图片

**层级：**

- 参考答案区块内常有与卷面一致的大题结构（如「一.选择题 1.A 2.B … 二.判断题 1.× 2.√ …」）。当前解析会识别这些大题标题行，并从答案列表中**过滤掉**（不把「一.选择题」当作某一题的答案），只保留按题号顺序的答案文本列表，再按**题目在文档中的顺序**一一回填到 `question.answer`。
- 题目本身已有 `section_title` / `section_order`（来自卷面大题），因此「哪道题属于哪一大题」已由卷面结构决定；参考答案区块的层级仅用于正确切分答案，**不再单独存成一份带层级的参考答案结构**。若前端需要按「一.选择题 / 二.判断题 / …」分块展示参考答案，可在展示层按题目的 `section_title` 分组后再渲染。

**图片：**

- 参考答案（及解析）中的图片与正文一样，会随 `_extract_paragraphs_with_images` 被抽出，在全文（含参考答案段落）中留下 `{{IMAGE_N}}` 占位符。按题号切分时，某题答案字符串中若包含占位符（如「如下：{{IMAGE_5}}」），会原样进入该题的 `answer`（或 `explanation`）。
- 在 consumer 的 `_upload_docx_images_and_replace_placeholders` 中，已对 **content、answer、explanation** 三个字段统一做占位符替换并写入 Markdown 图片语法，因此参考答案和解析里的图片会正确上传并显示。
